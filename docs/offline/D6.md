## Findings beyond the brief

1. Observed: the commit message of `7ddf3b400` says all changes are gated behind `CONFIG_M50mk2`. They
   are not. `src/init.c` at `walkback-milestone` fails to compile for `200D.101` and `50D.109`
   (`'m50ii_cbnode' undeclared` at line 1602 and others). At the upstream base the same file compiles.
2. Observed: `#define M50II_TRACE_CREATE_LADDER` (`src/boot-d678.c:14`) and the literal restore
   `*(RELOCADDR + 0xC8) = 0xE1394358` (`src/boot-d678.c:1304`) apply to every camera that uses
   `boot-d678.c` and defines `BR_BR_CSTART`; twelve other platforms define it (those built with `boot-d678.c` are affected).
3. Inferred: the literal restore is redundant on the M50 II. The corrupted source 0xE139F81D reported in
   docs/22 has the low half 0xF81D, which is the second half-word of a Thumb BL with offset 0x3A written
   at 0xC6; that is the old `BR_BR_CSTART`. With the current value 0xE00400C0 the 4-byte patch does not
   reach 0xC8. Not tested.
4. Observed: about 1,100 of the 1,276 lines added to `src/boot-d678.c` sit under `M50II_TRACE_*` macros
   that are never defined.
5. Observed: `fork/m50mk2-port` stops at `bb10c937b`. Commits `ecd2f853c`..`3ccf499dc` and `a10b16c23`
   are local only. `fa0834b40` (local `m50mk2-port` only) is the only commit holding `modules/wifidep/`,
   so the WiFi deploy lane of docs/37 is not in `walkback-milestone`.
6. Observed: the CamIF coprocessor re-init (`src/reboot.c:362`, ROM 0xE000690C) was missing from the
   brief's list of fixes and is documented in section 3.4.
