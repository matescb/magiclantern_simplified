# D5 - Merged Ghidra label proposals (offline sprint)

Agent D5, offline sprint on the Magic Lantern port to the Canon EOS M50 Mark II (DIGIC 8, firmware 1.0.1).
Everything here is static analysis of the ROM dump `m50ii_dumper/dump_1.0.1/gang100.bin` (ROM0, mapped at
0xE0000000, Thumb-2 code). **Nothing in this report was run on the camera, and nothing was written to the Ghidra
project.** The apply script was written but never executed.

## 3. Method

1. **Normalisation.** Addresses are written as `0x` plus eight lowercase hexadecimal digits. For code labels the
   Thumb bit (bit 0, which marks a pointer to Thumb code and is not part of the instruction address) is cleared.
   Observed: none of the 394 proposals had bit 0 set, so this changed nothing; the rule is still implemented in
   `d5_merge_labels.py` (`norm`) and again in `apply_labels.py`.
2. **Deduplication.** Rows are grouped by normalised address. The `evidence` column keeps every report's text,
   prefixed with the report id and separated by ` || `, so no evidence is lost.
3. **Refuted claims.** The "Independent verification" sections of A1..A9 and A13 were read for the verdict
   REFUTED and each hit was compared with that report's CSV (section 6).
4. **ROM check of every proposal.** `d5_merge_labels.py` disassembles each address with capstone and tests
   (a) that a code label is a function start and (b) that the addresses and quoted strings named in the evidence
   text are really referenced there (section 8).
5. **Conflict resolution.** For every address with two names the function was disassembled and one name chosen
   (section 4).
6. **Naming convention.** `ghidra/naming-conventions.md` was applied (section 7).

Ghidra (MCP server "ghidra") was used read-only for four `get_function_by_address` queries and one
`get_current_program_info`, to learn what the script will meet. Observed: the open program is `gang100.bin`,
language ARM:LE:32:Cortex, 52917 functions; `0xe05be8a6` and `0xe05b9f9e` are functions with default names
(`FUN_e05be8a6`, `FUN_e05b9f9e`); `0xe0753d9c` and `0xe06088ea` have **no function defined**, so for such rows
the script creates a label only.

## 7. Naming convention applied

From `ghidra/naming-conventions.md`:

- **Confidence tiers.** The convention forbids promoting a name to "OK" without QEMU or on-camera evidence, so no
  row is `OK`. `matched` (109 rows) means: the name is Canon's own text found in a string
  that the function or its registration site references, or the row is a string label whose text was read at the
  address, or the report shows the same structural offset as an existing stub on another camera model, or the
  existing M50 II stub already has this name at this address. `maybe` (252 rows) means a
  descriptive name derived from behaviour. The tier is in the `confidence` column; the convention allows either
  a `maybe_` name prefix or a `[hypothesis]` tag, and the script writes the tag (option `--comments`) and adds
  the prefix only with `--prefix-tiers`, so that names stay identical to the ones used in the reports.
- **Name families.** `edmac_*` for the EDMAC (Canon's image-data DMA controller) functions of report A5, in
  lower snake case; `task_*` for the nine task entry points of A11; `msg_handler_*` for the ten TaskClass message
  handlers of A11; `prop_handler_*` for the property handler of A4; `table_*` for 14 ROM tables; `g_<thing>` for
  the nine RAM globals, with the suffix `_maybe` when the tier is `maybe` (all nine).
- **Canon names are kept verbatim** (for example `fmMountCard`, `evfdevSendJob`, `SRM_AllocateMemoryResourceFor1stJob`),
  because they are quoted from firmware strings. `str_*` and `rom_src_*` data names are kept as proposed.
- **Existing stub names win** when they are not disputed: `_prop_cleanup` (A14b proposed `prop_cleanup`),
  `RegisterEDmacCompleteCBR`, `UnregisterEDmacCompleteCBR`, `CreateResLockEntry`, `UnLockEngineResources`.

## 8. Spot check

Automatic check, applied to all 397 rows (394 proposals + 3 added), implemented in
`docs/offline/tools/d5_merge_labels.py`:

- *Function start* (code labels): accepted if the first instruction is `push`, or the ROM contains a direct
  `bl`/`b.w` to the address (the script indexes every Thumb-2 BL/B.W target in ROM0), or the Thumb pointer
  `address|1` is stored as a 32-bit word in ROM0, or the preceding instruction is a function terminator.
- *Data labels*: ASCII text read at the address (strings), or the address found as a literal-pool word (tables,
  RAM globals).
- *Evidence*: each hexadecimal address and each quoted string in the evidence text is searched in the function
  body (literal loads, `adr`, branch targets), at its call sites, at the cited site, and in pointer tables.

Result over all 397 rows: PASS 375, PARTIAL 21, FAIL 1.
All 357 code rows are function starts (353 by push/caller/pointer, 4 only by "preceded by a terminator and no
static caller": `LoadCalendarFromRTC` 0xE0608794, `FromArea_Rom1Header_GetBase` 0xE027C2DC,
`edmac_reset_write_channel` 0xE05B96B8, `RscWrap_ClearFunctions` 0xE06088EA). PASS means that no evidence item
was contradicted. 313 of the 397 rows have at least one evidence address or string confirmed in ROM; for the
other 84 the verdict rests on the function-start (or data) check alone, because their evidence is a behavioural
description with nothing the script could test. PARTIAL means the function start is confirmed and at least one
named constant or offset was not re-derived. The single FAIL is the dropped A6 label.

## 9. The apply script

`docs/offline/labels/apply_labels.py` uses only the GhidraScript API (`currentProgram`, `getScriptArgs`,
`SymbolTable`, `FunctionManager`, `Listing`). Behaviour, as written (not tested in Ghidra):

- **Dry run by default**: prints one line per row (`RENAME_FUNCTION`, `CREATE_LABEL`, `SAME`, `KEEP`,
  `NAME_ELSEWHERE`, `INSIDE_FUNCTION`, `NO_MEMORY`, ...) and a summary; writes nothing. `--apply` writes.
- **No overwriting**: a symbol is replaced only if its source type is DEFAULT (`FUN_...`, `LAB_...`, `DAT_...`).
  USER_DEFINED, IMPORTED and ANALYSIS names are kept and reported.
- **No duplicates by default**: a name already present at another address is skipped (`--allow-duplicates` to
  override).
- Options: `--csv=`, `--comments` (plate comment with tier tag, sources, evidence, conflict; only where none
  exists), `--prefix-tiers`, `--create-functions` (off by default; where no function exists only a label is
  made), `--only=<report>`, `--min-confidence=matched`.
- It does not save the program; all writes are in the script's single transaction and can be undone.

Suggested order for the user: dry run; then `--apply --min-confidence=matched`; review; then the `maybe` rows.
