Nothing here has run on the camera. Host tests, build and symgate only.

## Result

Worktree `/mnt/data/WORK/eos/wt/H1`, branch `offline-plan-step3` (18 chars), commit `d39dd2a7a`
on top of `offline-plan-step2` (a015861a2). Module-only: 4 files in `modules/raw_video/raw_vidx`
(`event_pusher.c`, `worker.c`, `raw_vid.h`, `raw_vid_event_pusher.h`). The core `.sym` is
byte-identical to the baseline (md5 d2f46ba5...).

With the default sync source (`rvx_sync_src=0`) the per-frame hook
(`raw_vid_vsync_cbr` -> `rvx_frame_tick`) no longer waits on a semaphore, allocates, frees,
creates a task or prints over UART, on any branch including the error paths.

## What changed

| Before (G1) | Now |
|---|---|
| `get_empty_event()` in the hook: `take_semaphore(events_sem, 2000)`; on timeout UART + `task_create` | `get_frame_event()`: separate pool `frame_events[20]` used only by the frame tick, lock-free (one producer scans, the worker only writes `EMPTY`). Pool empty = frame dropped, `rvx_dropped_queue++` |
| Commands shared the same pool | `cmd_events[4]` + `events_sem` (timed take) for the key handler and the `stop_com` task only |
| `fio_malloc` x2 / `fio_free` in the hook (non-default toggles), `fio_free` on every idle vsync | Hook posts a reserved `CAPTURE_PREP` event (new event type); the worker calls `rvx_capture_alloc()`. Frames are skipped and counted in `rvx_dropped_nobuf` until the buffers exist. The worker frees them at stop (`rvx_capture_free()`) |
| Window does not fit: UART + `task_create("stop_com")` in the hook | `hook_request_stop()`: sets `prevent_recording`, posts a reserved `COMMAND_STOP` event with the non-blocking post; if the queue is full it is repeated on later vsyncs. Reason kept in `rvx_hook_flags` bit 0 and printed by the worker at stop |
| UART in the hook: "Video starting.", drop messages every 64th drop, 7 `RVX_HEX` lines on the first 3 frames | All removed from the hook. Drop totals and `hook flags` are printed by the worker at stop; the worker already prints `wk.src` / `wk.pitch` for the first frames |

Note on "zero-timeout try": `take_semaphore(sem, 0)` on DryOS waits for ever, so the task's
literal wording would have made things worse. The hook takes no semaphore at all instead.

Toggles and defaults are unchanged. New read-only telemetry: `rvx_hook_flags` (1 = window does
not fit, 2 = hook stop request found the queue full, 4 = capture buffers requested),
`rvx_dropped_nobuf`.

## Limits and open points

- `msg_queue_post` being non-blocking rests on the existing stub comment, not on a fresh
  disassembly.
- The lock-free pool assumes one producer at a time. That holds by construction (core hook for
  source 0, `rvx_sync` task for 1/2, the core hook returns early while `rvx_sync_active`), but
  was not tested under real preemption; the host harness is single-threaded.
- Key handler (`raw_vid_keypress_cbr`, Canon's GUI task) still prints and takes `events_sem`
  with a 2 s timeout. It is not the per-frame hook and was out of scope.
- Sources 1 and 2: the Canon-context part was already count + `give_semaphore` only (G1);
  `rvx_frame_tick` then runs in the `rvx_sync` task and is equally non-blocking now.
- Non-default toggles (`rvx_src_from_raw_info=0` / `rvx_redirect_edmac=1`): a session now loses
  its first one or two vsyncs while the worker allocates; the buffers are freed by the worker at
  stop while a hook call could in theory still be reading the pointers (the hook checks the
  recording state first). Default path is not affected.
- The first-frame geometry dump (`rawinfo.w/h/pitch/buf`, `src[0]`, `src[1]`) is gone from the
  UART log. If the hardware session needs it, it should be added to the worker, not the hook.
- With the queue full, a command post from `stop_com` can fail as before (retried 10 x 50 ms).
