# 06 - M50 II 1.0.1 symbol ledger (Ghidra documentation campaign)

Reverse-engineering campaign output for the Canon EOS M50 Mark II, firmware **1.0.1** (Digic 8, Thumb-2, DryOS 2.3).
Method: capstone string-anchoring (`tools/stubfind/stubfind.py`) on our own ROM dump `gang100.bin` (base `0xE0000000`),
cross-checked against the M50.110 sister port for names/ordering, with an **independent verify pass** per finding.
Every address below was located by an anchor **in our ROM** - M50.110 addresses were structural hints only, never copied.

**Coverage:** 8 subsystems, 81 targets - 62 OK, 4 matched, 5 maybe, 10 notfound. Plus 9 pre-campaign verified boot stubs (see `symbol-export/functions.csv`).

**Confidence:** `OK` = anchor + verified prologue/disasm; `matched` = structural analogy to M50.110, no independent anchor; `maybe` = plausible, weak evidence; `notfound` = no safe static anchor (needs runtime dump; address left blank, NOT copied).

> A wrong stub can hang/brick the camera. Only `OK` entries are safe to build against; treat `matched`/`maybe` as TODO-verify on QEMU or hardware.
